# nexus_transmitter — передача файлов между процессами

Консольная программа на C++17 под Linux: один исполняемый файл работает и
как сервер приёма, и как клиент отправки. Сторонние библиотеки не
используются — только стандартная библиотека и POSIX/Linux API.

## Сборка

```sh
cmake -S . -B build
cmake --build build -j
```

Результат — `build/nexus_transmitter`.

## Запуск

```sh
# сервер: постоянно ждёт подключений, по умолчанию сохраняет файлы в каталог программы
./build/nexus_transmitter -s

# клиент: отправляет файл и завершается
./build/nexus_transmitter -c <путь_к_файлу> [опции]
```

Принятый файл сохраняется как `ГГГГММДД_ЧЧММСС.hex` (побайтовая копия
исходного файла). При совпадении имени (несколько передач в одну секунду)
добавляется суффикс `_001` … `_999`.

`--help`/`-h` печатает эту же справку.

## Опции

| Опция | Режим | Назначение |
|---|---|---|
| `--port <порт>` | оба | порт TCP, по умолчанию 5555 |
| `--host <адрес>` | клиент | адрес сервера, по умолчанию 127.0.0.1 |
| `--destination <адрес>` | оба | адрес целиком вместо `--host`/`--port`, например `127.0.0.1:5555` или `[::1]:5555` |
| `--dir <путь>` | сервер | куда сохранять файлы, по умолчанию каталог программы |
| `--max-sessions <N>` | сервер | предел одновременных передач, по умолчанию 1024 |
| `--timeout <сек>` | оба | таймаут неактивности (сервер — 30, клиент — 15) |

У сервера нет отдельного флага `--host` — по умолчанию он слушает на всех
сетевых интерфейсах машины (`0.0.0.0`), не только на `127.0.0.1`. Изменить
это можно через `--destination` (например, `--destination 192.168.1.5:5555`,
чтобы слушать только на конкретном интерфейсе).

## Пример

```sh
./build/nexus_transmitter -s --dir /tmp/incoming --port 6000 &
./build/nexus_transmitter -c report.pdf --port 6000

# то же самое, адрес одной опцией
./build/nexus_transmitter -c report.pdf --destination 127.0.0.1:6000
```
